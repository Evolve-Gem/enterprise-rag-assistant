# Agent Loop、State 与停止条件

> [!summary] 一句话总结
> **Agent Loop是Agent反复读取状态、决定行动、调用工具、接收结果并继续判断的循环运行机制；State是保存当前任务信息、中间结果和执行进度的结构化数据；停止条件则规定循环何时成功结束、暂停或因限制终止。**

## 1. Agent Loop是什么？

Agent Loop是Agent为了完成目标，反复执行以下步骤的循环运行机制：

```text
读取当前状态
→ 决定下一步行动
→ 调用Tool或生成回答
→ 接收执行结果
→ 更新State
→ 再次判断
→ 直到任务结束
```

一次性大模型调用：

```text
输入
→ 模型
→ 输出
```

Agent Loop：

```text
输入
→ 判断
→ 行动
→ 获得新信息
→ 再判断
→ 再行动
→ 完成任务
```

Agent Loop的关键是：

> 后续行动会根据前面行动产生的中间结果发生变化。

## 2. Tool到底由谁执行？

模型不会直接进入数据库、运行Python或修改文件。

模型通常只生成Tool Call请求，例如：

```json
{
  "tool": "query_sales_data",
  "arguments": {
    "brand": "竞品A",
    "period": "最近四周"
  }
}
```

外围程序负责：

```text
读取Tool名称和参数
→ 校验权限与参数
→ 执行真实Tool
→ 获得结果
→ 把结果返回给模型
```

因此：

- 模型负责选择并提出行动
- 程序负责真正执行行动
- Harness负责权限、日志、错误和循环控制

## 3. State是什么？

State是Agent在当前任务运行过程中，用来保存任务信息、中间结果和执行进度的结构化数据集合。

State中可能保存：

- 用户原始问题
- 当前目标
- 分析对象和时间范围
- 当前执行步骤
- 已调用的Tool
- Tool执行结果
- 检索资料
- 错误信息
- 审批状态
- 执行轮数
- 最终结果

一句话理解：

> State是Agent完成当前任务时使用的工作记录。

## 4. 为什么需要State？

Agent通常需要完成多个步骤。

State帮助后续步骤知道：

- 用户最初要求什么
- 已经完成了什么
- 上一步得到了什么结果
- 哪些Tool已经调用
- 哪些任务还没有完成
- 当前是否出现错误
- 是否已经获得人工批准

没有State，Agent可能忘记中间结果，重复执行相同动作，或者无法判断任务是否完成。

## 5. State、Context与Memory

| 概念 | 核心问题 |
|---|---|
| State | 当前任务进行到哪一步？ |
| Context | 模型这一轮能够看到什么？ |
| Memory | 过去哪些信息以后还要继续使用？ |

程序可能从State中挑选当前判断所需的信息，组织成Context发送给模型。

```text
State保存任务信息
→ 选取当前需要的内容
→ 组成模型当前Context
```

State中的内容不一定全部进入Context。

Memory通常用于跨对话或跨任务保存用户偏好、历史状态和长期经验。

## 6. 停止条件是什么？

停止条件是Agent Loop结束、暂停或转入人工处理的明确判断规则。

常见停止条件包括：

### 任务成功完成

- 已取得必需数据
- 已完成计算
- 已生成完整结果
- 已通过规则或人工检查

### 模型不再请求Tool

模型直接生成最终答案，但程序仍可检查答案是否满足业务要求。

### 达到最大轮数

例如最多允许十次Tool调用。

最大轮数属于安全兜底，不代表任务已经成功。

### 超过时间、成本或Token预算

系统因资源限制结束任务。

### 发生无法恢复的错误

例如没有权限、数据不存在或接口持续不可用。

### 等待人工审批

高风险操作需要暂停，等待人工批准后继续。

## 7. 成功条件与兜底条件

成功条件表示：

> 用户目标已经真正完成。

兜底条件表示：

> 系统不能再继续运行。

最终状态可以区分为：

```text
SUCCESS：成功完成
NEED_HUMAN：等待人工
INSUFFICIENT_DATA：信息不足
FAILED：执行失败
LIMIT_REACHED：达到运行限制
```

> Agent停止不等于Agent成功。

## 8. 为什么会出现无限循环？

常见原因：

- 没有明确成功标准
- Tool结果没有写入State
- 没有记录已执行动作
- Tool错误信息不清楚
- 路由规则没有通往结束节点
- 模型不断认为还需要继续完善
- 没有最大轮数和预算限制

可靠Agent需要：

- 明确的完成标准
- 当前步骤记录
- 已执行动作记录
- 最大轮数限制
- 错误和重试规则
- 人工介入机制

## 9. Agent Loop、State与Harness

```text
Agent Loop
负责推动任务不断运行

State
负责记录任务进行到哪里

Harness
负责承载和控制整个循环
```

Harness可能负责：

- 调用模型
- 解析Tool Call
- 执行Tool
- 更新State
- 构建Context
- 判断停止条件
- 控制最大轮数
- 记录Trace
- 处理权限和人工审批

## 10. 商业分析案例

```text
用户提出竞品分析目标
→ Agent查询销量数据
→ State保存销量结果
→ Agent发现SKU异常
→ 调用SKU与渠道分析Tool
→ State保存分析结果
→ Agent调用RAG检索市场资料
→ State保存证据
→ Agent判断证据是否充分
→ 生成事实、假设与待验证事项
→ Harness检查完成条件
→ 输出最终报告
```

## 11. 可直接复述的标准表述

> Agent Loop是Agent在完成任务时反复读取当前状态、决定下一步、调用工具、接收结果并更新状态的循环运行机制。State是用于保存当前任务信息、中间结果和执行进度的结构化数据。停止条件则规定Agent在任务完成、需要人工介入、发生错误或达到运行限制时结束或暂停循环。Agent Loop负责推动任务运行，State负责记录进行到哪里，Harness负责执行工具、更新状态并控制整个循环。
