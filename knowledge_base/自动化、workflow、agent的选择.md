# 自动化、AI Workflow 与 Agent 的选择

> [!summary] 一句话总结
> **自动化是按照固定规则自动执行确定性任务的技术方式；AI Workflow是按照预先设计的流程组合模型、Tool和规则完成任务的系统；Agent则是能够根据任务状态和中间结果动态决定下一步行动并调用工具的AI系统。**

## 1. Automation｜自动化

自动化是按照预先设定的规则和程序，自动执行确定性任务的技术方式。

典型特征：

```text
输入固定
+ 规则固定
+ 步骤固定
+ 输出相对确定
```

适合：

- 定时下载数据
- 合并Excel
- 指标计算
- 阈值提醒
- 固定格式导出

自动化不一定需要大模型。

## 2. AI Workflow｜AI工作流

AI Workflow是按照预先设计的步骤、顺序和分支，组合大模型、Tool、规则与人工节点完成任务的流程系统。

例如：

```text
读取数据
→ Python计算指标
→ 检索指定资料
→ 大模型生成摘要
→ 人工审核
```

即使使用了大模型，只要整体路线和Tool调用顺序基本固定，仍然更接近Workflow。

## 3. Agent｜智能体

Agent是一种**围绕目标运行**，能够根据**任务、环境状态和中间结果，动态决定**下一步行动**并调用相应Tool**的**AI系统。**

Agent可能动态判断：

- 还缺少什么信息
- 应该调用哪个Tool
- 是否继续检索
- 是否调整分析维度
- 是否向用户追问
- 什么时候结束任务

## 4. 三者的区别

| 类型 | 核心特点 | 适合任务 |
|---|---|---|
| 自动化 | 固定规则自动执行 | 确定性任务 |
| AI Workflow | 流程预先设计，大模型参与部分环节 | 稳定重复任务 |
| Agent | 根据中间结果动态决策和调用Tool | 开放、多步骤任务 |

三者不是简单的低级、中级和高级关系。

> 应选择能够以最低复杂度、最高稳定性解决业务问题的方案。

## 5. 判断方法

### 规则能否完全写清？

可以：

> 优先使用自动化。

### 执行步骤是否基本固定？

固定，但需要模型理解或生成：

> 优先使用AI Workflow。

### 是否需要根据中间结果改变路线？

需要：

> 可能适合Agent。

### 是否需要动态选择多个Tool？

需要系统自主判断查数据库、检索文档、运行Python或向用户追问：

> 更接近Agent。

### 自主决策风险是否可控？

高风险场景必须加入：

- 权限控制
- 规则约束
- 人工审核
- 日志和Trace
- Evaluation

## 6. 商业分析场景

### 固定周期报告助手

```text
读取固定数据
→ 计算固定指标
→ 生成固定摘要
→ 人工审核
```

优先考虑自动化或AI Workflow。

### 指标口径查询助手

```text
用户提问
→ RAG检索资料
→ 生成带来源回答
```

优先考虑RAG Workflow。

### 复杂竞品分析助手

当系统需要动态判断：

- 是否分析SKU
- 是否拆分渠道
- 是否查看区域
- 是否检索市场事件
- 是否追问用户

才更接近Agent。

第一版仍可以先用固定Workflow验证价值，再逐步增加动态决策能力。

## 7. 核心原则

> 能用规则稳定解决的，不交给大模型；能用Workflow稳定解决的，不急着做复杂Agent。

使用复杂Agent可能增加：

- 开发成本
- 运行成本
- 执行时间
- 结果波动
- 调试难度
- 权限风险

## 8. 可直接复述的标准表述

> 是否使用Agent，需要根据业务任务的动态程度判断。规则和步骤完全固定的任务适合普通自动化；流程固定但部分环节需要大模型理解和生成的任务适合AI Workflow；只有系统需要根据中间结果动态选择Tool、调整步骤或向用户追问时，才更需要Agent。第一版应优先使用最简单、稳定并且容易评估的方案。
