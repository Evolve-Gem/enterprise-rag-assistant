# Evaluation、Evaluation Harness 与闭环调优

> [!summary] 一句话总结
> **Evaluation是一套通过测试案例、评分标准和结果对比，系统衡量AI系统是否达到预期要求的方法；Evaluation Harness是端到端执行评估的基础设施；闭环调优是根据运行记录和评估反馈持续修改系统并重新验证的迭代优化机制。**

## 1. Evaluation｜评估

### 权威定义

Evaluation是一套通过测试输入、参考结果和评分标准，对AI系统输出进行系统验证和质量衡量的方法。

它主要回答：

> Agent到底好不好？新版本究竟有没有变好？

### Evaluation的基本组成

- 评估目标
- 测试集
- 预期结果
- 评分标准
- Grader评分器
- 评估指标
- 新旧版本对比

### 为什么跑通不等于做好？

程序成功返回内容，只能说明技术链路能够运行，不能证明：

- 检索正确
- 数据计算正确
- 回答完整
- 引用可靠
- 没有幻觉
- 在不同问题下稳定
- 能够创造业务价值

## 2. Dataset｜测试集

测试集是一组用于稳定测试Agent的代表性任务案例。

测试内容应覆盖：

- 正常问题
- 边界问题
- 资料缺失
- 资料冲突
- 错误数据
- 模糊表达
- 多Tool协作
- 引用证据要求

真实运行中发现的新失败案例，也应该逐步加入测试集。

## 3. Grader｜评分器

Grader是按照明确标准对Agent结果进行评分的方法。

常见方式：

- 规则评分
- 标准答案对比
- 人工专家评分
- 模型评分
- 新旧版本两两比较

评分标准应尽量具体，例如：

- 是否包含关键事实
- 是否引用正确来源
- 是否区分事实和假设
- 是否符合输出格式
- 是否出现禁止编造的结论

## 4. 评估指标

### 检索层

- Context Recall
- Context Precision
- 关键证据命中率
- 正确资料是否进入最终Context

### 回答层

- 事实正确性
- 完整性
- 相关性
- 依据资料程度
- 引用准确性
- 格式稳定性

### 业务层

- 人工处理时间是否下降
- 报告是否可以直接使用
- 人工修改量是否下降
- 业务人员是否愿意使用

技术指标变好，不一定代表业务价值一定提高，因此二者需要分别评估。

## 5. Evaluation Harness｜评估执行框架

### 权威定义

Evaluation Harness是一套负责端到端运行评估任务的基础设施。

它通常负责：

```text
读取测试集
→ 准备指令、Tool和测试环境
→ 批量运行Agent
→ 记录全部执行步骤
→ 保存最终结果
→ 调用Grader评分
→ 汇总指标
→ 比较不同版本
```

一句话区分：

> Evaluation定义考什么和怎样判分，Evaluation Harness负责把整套考试稳定运行起来。

## 6. Agent Harness与Evaluation Harness

### Agent Harness

负责支撑Agent日常运行，例如：

- 上下文管理
- Tool连接
- 权限
- 日志
- 重试
- 审批
- 沙箱

### Evaluation Harness

专门负责：

- 批量运行测试
- 记录测试过程
- 调用评分器
- 汇总结果
- 比较版本

“Harness”在不同语境下范围不同，需要根据上下文判断具体指哪一种。

## 7. Trace｜运行轨迹

Trace是Agent一次任务从输入到输出的完整过程记录。

可能包括：

```text
用户问题
→ 意图判断
→ Skill选择
→ Tool调用
→ 数据库结果
→ RAG召回内容
→ Rerank结果
→ 最终Context
→ 模型回答
```

Evaluation告诉我们：

> 结果得了多少分。

Trace帮助我们判断：

> 为什么得到这个分数。

## 8. 闭环调优

### 定义

**闭环调优是一种以真实运行记录和评估结果为反馈，持续定位失败原因、修改系统并重新评估的迭代优化机制。**

完整流程：

```text
运行Agent
→ 保存Trace和结果
→ 收集用户与人工反馈
→ 找出失败案例
→ 加入测试集
→ 分类定位错误
→ 修改对应模块
→ 重新运行Evaluation
→ 对比新旧版本
→ 上线后继续收集反馈
```

或者：
开发 Agent
        ↓
建立测试集
        ↓
自动运行
        ↓
自动评分
        ↓
发现问题
        ↓
优化召回
        ↓
优化 Prompt
        ↓
优化知识库
        ↓
再次测试

仅仅发现问题后随手修改Prompt，再测试一个问题，不算稳定的闭环调优。

## 9. 不同问题应该调什么？

### 正确资料没有召回

优化：

- 文档解析
- Chunk切分
- 查询改写
- 检索方式
- 初始候选数量

### 资料召回但排序靠后

优化：

- Rerank
- 相关性评分
- 元数据过滤
- Top K

### 正确资料进入Context但回答错误

优化：

- Context组织
- Prompt
- 模型理解
- 引用约束
- 事实与推测区分

### 数据计算错误

优化：

- Python或SQL
- 指标口径
- 数据清洗
- 计算规则

### 输出格式不稳定

优化：

- 输出模板
- JSON Schema
- 格式校验
- 重试机制

## 10. 竞品分析Agent评估示例

每个测试案例可以记录：

| 字段 | 内容 |
|---|---|
| 测试问题 | 用户提出的问题 |
| 预期检索内容 | 应命中的资料 |
| 必须包含 | 答案中的关键事实 |
| 禁止出现 | 不得编造的结论 |
| 输出要求 | 报告格式 |
| 人工评分 | 结果是否可用 |
| 错误类型 | 检索、计算、生成或流程 |

## 11. 可直接复述的标准表述

> Evaluation是一套通过测试案例、评分标准和结果对比，系统衡量AI系统是否达到预期要求的方法。Evaluation Harness是端到端执行这些评估的基础设施，负责运行任务、记录步骤、调用评分器并汇总结果。闭环调优则是根据真实运行记录和评估结果定位失败原因，修改检索、Prompt、规则、Tool或Harness，再使用同一套测试重新验证的持续迭代机制。

## 核心结论

- Evaluation负责判断好不好
- Evaluation Harness负责把考试跑起来
- Trace负责记录为什么会得到这个结果
- 闭环调优负责根据结果持续改进
- 失败案例应当沉淀为新的测试案例
- Agent优化必须基于证据，而不是只靠主观感觉
