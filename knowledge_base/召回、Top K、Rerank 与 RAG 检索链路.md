# 召回、Top K、Rerank 与 RAG 检索链路

> [!summary] 一句话总结
> **RAG 检索链路是一套从外部知识源中寻找候选资料、筛选并排序相关内容，再把高质量证据放入模型 Context 的信息处理流程/技术模式**

## 1. Retrieval｜检索

### 权威定义

检索是根据用户查询，从外部知识源中寻找并返回相关候选内容的过程。

检索阶段通常返回：

- 文档
- Chunk
- 网页
- 数据记录
- 候选证据

检索负责找到资料，不直接等于生成最终答案。

## 2. 召回的两种含义

### 作为检索过程

“召回 20 个 Chunk”表示检索系统从知识库中找回了 20 个候选片段。

### 作为评估指标

Recall 表示知识库中所有真正相关的内容里，有多少被系统成功找到。

```text
Recall
=
检索到的相关内容数量
÷
知识库中全部相关内容数量
```

Recall 关注：

> 该找到的资料，有多少没有被漏掉？

## 3. Precision｜查准率

Precision 表示系统检索出来的内容中，有多少是真正相关的。

```text
Precision
=
检索到的相关内容数量
÷
系统检索出的全部内容数量
```

Precision 关注：

> 找回来的资料中，有多少不是无关内容？

一句话区分：

> Recall 怕漏，Precision 怕乱。

## 4. Top K

Top K 是检索系统按照相关性分数排序后，返回排名最靠前的 K 个候选结果。

例如：

```text
Top K = 5
```

表示只返回相关性排名前 5 的文档片段。

Top K 太小：

- 容易漏掉关键证据
- Recall 可能下降
- 信息可能不完整

Top K 太大：

- 无关内容增加
- 占用 Context
- 增加 Token 成本
- 资料之间可能冲突
- 模型可能抓不住重点

因此 Top K 不是越大越好，需要通过测试确定。

## 5. Rerank｜重排序

### 权威定义

Rerank 是对初次检索得到的候选结果进行再次相关性评分和排序，以提升最相关内容排名的技术步骤。

典型两阶段检索：

```text
知识库
→ 初次检索 30 个候选
→ Rerank 重新评分
→ 选择最终 Top 5
→ 放入 Context
```

第一次检索的重点是：

> 快速找到一批可能相关的候选，尽量不要漏。

Rerank 的重点是：

> 在候选范围内更准确地判断谁最相关。

### Rerank 的边界

Rerank 只能重新排列已经检索出来的候选内容。

如果正确资料没有进入第一次候选集合，Rerank 无法凭空把它找回来。

```text
没有召回正确资料
→ 优化初次检索

已经召回但排序不好
→ 优化 Rerank
```

## 6. 三种常见检索方法

### 关键词检索

根据关键词和文本匹配寻找资料。

适合：

- 指标缩写
- SKU 编码
- 产品名称
- 专有名词
- 精确表达

局限：

用户问题和文档表达不一致时，可能检索不到。

### 向量检索

将查询和资料转换成向量，根据语义相似度寻找相关内容。

适合：

- 自然语言问题
- 同义表达
- 问题和文档用词不同
- 按语义查找资料

### 混合检索

同时执行关键词检索和向量检索，再融合两类结果。

优势：

- 关键词检索抓精确术语
- 向量检索抓语义相关
- 两种方式互相补充

## 7. 完整检索链路

```text
用户提出问题
→ 查询理解或改写
→ 关键词、向量或混合检索
→ 召回候选 Chunk
→ 权限、时间和类型过滤
→ Rerank 重新评分
→ 选择最终 Top K
→ 去重并组织 Context
→ 大模型生成回答
→ 返回答案和资料来源
```

## 8. 竞品分析案例

用户提出：

> 竞品 A 最近四周销量增长可能与哪些动作有关？

系统可以：

1. 提取竞品、时间范围和分析目标
2. 检索新品、促销、价格和渠道资料
3. 召回一批候选 Chunk
4. 使用 Rerank 判断哪些资料最相关
5. 选择最终 Top K 放入 Context
6. 让模型区分数据事实、相关事件和原因假设
7. 返回结论、证据来源和待验证事项

## 9. 如何定位问题？

### 正确资料完全没找到

重点检查：

- 文档解析
- Chunk 切分
- 索引
- 查询理解
- 检索方法
- 初始 Top K

属于召回问题。

### 正确资料找到了，但排名靠后

重点检查：

- 相关性评分
- 排序规则
- Rerank
- 关键词权重

属于排序问题。

### 正确资料已进入 Context，但回答仍错误

重点检查：

- Context 组织
- Prompt
- 模型理解
- 生成过程
- 资料冲突

属于上下文或生成问题。

## 10. 可直接复述的标准表述

> 召回在工程中可以指检索系统找回候选内容的过程；作为指标时，Recall 表示所有真正相关的资料中有多少被成功找到。Top K 是按照相关性排序后返回排名前 K 的候选结果。Rerank 是在初次检索后，对候选资料重新评分和排序的技术步骤。一个常见的 RAG 检索链路是先通过关键词、向量或混合检索召回候选资料，再进行 Rerank，最终选择少量高相关内容放入模型 Context。

## 11. 核心结论

- 检索负责找候选资料
- Recall 关注是否漏掉相关内容
- Precision 关注检索结果是否混入过多无关内容
- Top K 需要平衡遗漏和噪声
- Rerank 只能重排已有候选，不能挽救完全未召回的资料
