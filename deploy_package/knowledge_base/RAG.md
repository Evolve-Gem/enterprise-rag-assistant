# RAG 与知识库的区别和关系

> [!summary] 一句话总结
> **RAG是先从外部知识库中检索与问题相关的内容，再把检索结果提供给大模型，辅助模型生成有依据的回答的技术模式**

## 1. 权威定义

RAG全称为Retrieval-Augmented Generation，中文通常译为“检索增强生成”。

它是一种将外部信息检索系统与大语言模型结合的技术模式：

```text
用户提问
→ 检索外部资料
→ 将相关资料放入Context
→ 大模型根据资料生成回答
```

## 2. 三个组成部分

### Retrieval｜检索

从外部知识库中找到与用户问题相关的资料。

### Augmented｜增强

把检索到的资料加入模型当前的Context。

### Generation｜生成

模型结合用户问题和检索资料生成回答。

## 3. 通俗理解

普通大模型主要依靠训练时学到的知识回答。

RAG相当于让模型在回答前，先去指定资料库中找到相关文件，再根据文件回答。

RAG的重点不是让模型本身变得更聪明，而是让模型当前拿到更相关、更可信、更及时的资料。

## 4. RAG的价值

- 使用企业内部或行业专属知识
- 补充模型训练后新增的信息
- 让回答可以标注资料来源
- 降低模型凭空编造的风险
- 方便更新业务知识，而不必重新训练模型

RAG只能降低幻觉风险，不能保证回答绝对正确。

## 5. RAG与知识库

知识库负责保存资料，例如：

- 产品文档
- 业务制度
- 竞品报告
- FAQ
- 会议纪要

RAG负责：

```text
根据当前问题检索知识库
→ 取出相关内容
→ 交给大模型
→ 生成回答
```

> 知识库是资料仓库，RAG是使用仓库资料帮助模型回答问题的流程。

## 6. RAG与搜索

搜索通常返回文档、网页、链接或相关片段。

RAG会在检索后继续完成：

```text
检索结果
→ 放入模型Context
→ 理解和整理
→ 生成面向用户的回答
```

检索是RAG中的一个环节，RAG还包含上下文增强和答案生成。

## 7. RAG与Agent

RAG解决：

> 回答当前问题需要依据哪些外部知识？

Agent解决：

> 为了完成用户目标，应该采取哪些步骤、调用哪些能力？

Agent可以把RAG作为一个Tool或Skill调用，但RAG本身不一定是Agent。

```text
用户目标
→ Agent判断任务
→ 调用RAG检索资料
→ 调用其他Tool处理数据
→ 生成最终结果
```

## 8. RAG与Memory

RAG知识库主要保存：

- 产品知识
- 业务制度
- 行业资料
- 企业文档

Agent Memory主要保存：

- 历史对话
- 用户偏好
- 任务状态
- 过去的执行结果

知识库解决“应该参考什么业务知识”，Memory解决“过去发生了什么，需要继续记住什么”。

## 9. RAG与微调

RAG是在回答前临时检索资料，并放入Context。

微调是通过训练数据调整模型参数，使模型形成特定的行为或能力。

> RAG主要解决模型应该参考什么知识，微调主要解决模型应该以什么方式表现。

## 10. 竞品分析案例

用户提出：

> 分析竞品A最近销量上涨的可能原因。

RAG可以检索：

- 历史竞品报告
- 新品发布资料
- 促销信息
- 渠道活动
- 行业新闻
- 已有分析结论

流程：

```text
用户提出问题
→ 检索相关资料
→ 将资料放入Context
→ 模型生成分析结论
→ 标注证据来源
→ 人工复核
```

RAG可以提供证据和原因线索，但不能直接证明某个市场事件一定导致销量增长。

## 11. 常见误区

### 上传文档不一定等于RAG

直接把整份文档放进Context，更接近长上下文问答。

RAG强调根据当前问题检索相关片段。

### 知识库有答案不代表一定能回答

还可能受到以下环节影响：

- 文档解析
- 文档切分
- 索引构建
- 查询理解
- 召回
- 排序
- Context组织
- 模型生成

### RAG不能彻底消除幻觉

RAG仍然需要：

- 高质量资料
- 良好的检索
- 清晰的Prompt
- 引用来源
- 人工审核
- 效果评估

## 12. 可直接复述的标准表述

> RAG全称是检索增强生成，是一种把外部信息检索与大语言模型结合的技术模式。系统先从知识库中检索与用户问题相关的内容，再把这些内容放入模型的Context中，辅助模型生成更有依据的回答。知识库负责存储资料，检索负责找到资料，大模型负责理解与生成。RAG可以降低幻觉风险，但最终效果仍取决于资料质量、检索质量和生成质量。
