## 2. Target User

**Primary**：扫简历二维码进入的 HR / 招聘 / 面试官。

- 不一定懂 RAG / Agent；没有时间研究导航；第一次访问可能只有 30 秒 ~ 3 分钟；很可能用手机。

**Secondary**：AI 产品经理 / AI 应用工程师 / 解决方案工程师 / 技术面试官。

- 会继续查看引用下钻、Agent Trace、RAG 评测、知识探索、系统设置。

因此信息层级固定为：**产品价值 → 用户任务 → 技术能力**。进入产品不会被首先塞一堆工程术语。

## 5. Homepage（`/`）

自上而下的模块：

1. **Hero**：`ENTERPRISE RAG COPILOT` + 主标题 + 「基于企业知识库，实现可溯源知识问答、AI Agent 任务执行与售前方案生成。」；
   技术栈（Hybrid RAG / LangGraph / 公开只读 Demo）作为**低权重灰底小标签**放在价值主张之后。
2. **三个核心入口**：知识问答 / AI 任务 / 方案生成，各含一句说明 + 动词 CTA（开始提问 / 运行 Agent / 生成方案）。
   桌面三列等宽，手机纵向堆叠。
3. **3 分钟体验**：Step 1 / Step 2 / Step 3，各自给出示例、流程箭头（如「检索企业知识 → 筛选证据 → 生成回答 → 标注来源」）与按钮。
   每张卡片底部注明「只填入示例内容，不会自动提问」。
4. **核心能力**：可溯源知识问答 / AI 任务执行 / 售前方案生成 / 知识洞察，标题全部用业务语言。
5. **它是怎么工作的**：业务层五步（企业资料 → 知识检索 → 证据筛选 → AI 生成 → 可验证结果），
   下方「技术实现」表（Markdown/PDF/DOCX · BM25 + Vector · RRF · Heuristic Rerank · DeepSeek · LangGraph Agent）。
6. **当前 Demo 状态**：原有 Dashboard 整体下沉，真实数据（文档数 / 知识块 / 检索模式 / Agent 运行 / 问答次数 / 平均响应 /
   带来源回答比例 / 执行引擎）+ 知识覆盖 / 资料分类分布 / 最近活动 / 最近文档 / 最近提问。
   手机端为双列，不占首屏。

**引导不做成强制流程**：三个入口互相独立，没有 Next / Skip，没有模态弹窗。

## 6. Core Tasks

### 6.1 知识问答 `/ask`

- 页面引导：「向企业知识库提问。AI 会先查找相关资料，再基于证据回答并标注来源。」
- 输入框 placeholder 用真实示例；下方「不知道问什么？试试这些」四个示例 Chip，**只填空不自动提问**。
- 支持 `?q=` 预填（来自首页 3 分钟体验）。
- 回答生成后新增「**这次回答发生了什么**」：检索企业知识库 → 找到相关证据 → 重排序 → 基于证据生成回答，
  并给出「共检索 N 个候选片段，筛选后保留 M 段作为回答依据，其中 K 处被正文引用」。
- 「**查看技术过程**」默认**折叠**，展开后才显示检索模式 / 候选片段 / BM25 命中 / 向量命中 / 融合策略 / 重排器 / Top K / 耗时。

> 示例 Chip 用的是与本地知识库**实际命中**的问法（而非任务书里的改写版），
> 因为一个点了没结果的 Chip 比没有 Chip 更伤第一印象。语义一致，仅措辞按知识库对齐。

### 6.2 AI 任务 `/agent`

- 页面引导：「告诉 Agent 你希望完成什么。它会自动识别任务类型，选择对应能力并执行。」
- 示例任务改为产品级的四条（知识缺口分析 / 知识库综述 / 优化建议 / 方案生成）；支持 `?task=` 预填。
- 执行完成后，在现有 Trace **之前**插入「**刚刚发生了什么**」：识别任务（用后端给的中文意图标签）/ 选择能力 /
  调用工具数 / 执行步骤数，并给出耗时、使用的证据段数与引用数。
  这些数字**全部来自真实执行记录，不由模型生成**。
- 该区块右上角提供「查看完整执行轨迹 ↓」，平滑滚动到既有 Trace 标签页。
- 技术面板（执行轨迹 / Tool 调用 / 执行计划 / 中间分析结果）原样保留在下方。

### 6.3 方案生成 `/solution-studio`

- 页面引导：「输入客户需求，AI 会理解需求、检索相关企业知识，并生成带来源依据的结构化售前方案。」
- 表单上方新增「**快速体验示例**」：一键填入「职业院校知识库」预设，并注明不会自动生成。
- 生成按钮上方新增「**你将得到**」：需求分析 / 推荐方案 / 实施路径 / 风险说明 / 参考依据 / 可导出 Markdown / Word。
- 生成完成后新增「**本次方案生成过程**」：理解需求 → 提取检索问题 → 检索企业知识 → 组织方案 → 添加引用，
  并给出章节数、带引用章节数、证据段数与引用处数。
- 支持 `?requirement=` 预填。

### 6.4 知识洞察 `/insights/gaps`

- 用户可见名称改为「知识洞察」，副标题「查看企业知识资产当前覆盖了什么、还缺少什么」。
- `covered / partial / missing` 在 UI 主层为「已覆盖 / 部分覆盖 / 缺失」，英文状态码降为灰字次标签。
- 明确「覆盖判定基于规则与真实资料匹配，不是 AI 随机评分」，不新增任何"准确率"类指标。

### 6.5 RAG 评测 `/insights/evaluation`

- 导航名改为「RAG 评测」；顶部引导说明：这不是「AI 自己给自己打的分数」，而是用固定测试集检验检索是否真的找到正确资料。
- 新增「**这些指标怎么读**」：先用用户语言（正确资料有没有进入前 K 个结果 / 通常排得有多靠前 /
  应该找到的找回了多少 / 回答依据覆盖了多少关键词），下方一行给技术定义。
- 指标卡片 hint 同步改为用户语言；数据集管理与人工评分流程不变。

## 7. Mobile

- 断点策略：`md`（768px）以下侧边栏改为**左侧抽屉**（汉堡入口在顶栏），768px 及以上保持固定侧边栏。
- 顶栏在小屏隐藏状态徽标（服务正常 / 公开只读演示），避免与标题争宽。
- 三个核心入口卡片：手机纵向；「3 分钟体验」卡片：手机纵向；核心能力：手机单列；当前 Demo 状态：手机双列。
- 引用抽屉 `Drawer` 本身就是 `w-full`，在手机上即全屏 sheet，无需额外改造。
- Agent Trace、表格（`Table` 自带 `overflow-x-auto`）、Tabs（自带横向滚动）在窄屏走滚动容器，不撑破 viewport。
- 方案生成本来就是「xl 以下单栏」，手机自然为 输入 → 需求解析 → 方案 的单栏顺序。

**实测（见 §9）**：390×844 与 430×932 横向溢出均为 0。

## 8. About `/about`

不写成个人简历页，而是 Product Story，六个部分：

- **A 为什么做这个产品**：企业知识散落在产品资料 / FAQ / 案例 / 解决方案 / 内部文档；传统搜索能找到文件，
  但难以直接回答问题、说明依据、执行任务、发现缺口。
- **B 产品解决什么问题**：找不到 / 说不清 / 做不完 / 不知道哪里缺 / 不知道效果如何 → 各自链到可现场验证的页面。
- **C 核心链路**：Knowledge → Retrieval → Rerank → Grounded Generation → Agent / Skill / Tool → Trace → Evaluation。
- **D 当前 Demo**：文档数、知识块、检索模式、工作流引擎、业务能力数、可执行动作数、版本、访问模式 ——
  **全部来自 `/api/overview` 实时返回，没有任何硬编码数字**。
- **E 项目边界**：单实例 Demo、非多租户、无完整企业权限体系；向量存储默认 numpy，pgvector 未作为生产默认；
  扫描 PDF 无 OCR；未做高并发压测；回答质量只接受人工评分。
- **F 项目角色**：Product Design / RAG Architecture / Agent Workflow / Full-stack Implementation / Evaluation & Deployment，措辞克制。

末尾「想继续深入？」给出引用下钻、执行轨迹、检索指标、知识块探测、系统自检五个入口，方便技术面试官。

## 12. Known Issues

1. **线上仍是 V3**。本轮只在本机完成验收；`https://rag.changziqi.com` 尚未部署 V4。
   部署需要显式的生产授权（本项目长期约定：生产部署不自动执行）。
2. **首页在手机上仍然很长**（双列后约 6.8k px / DPR2）。原因是按要求保留了完整的「当前 Demo 状态」区块。
   若希望更短，可把该区块折叠为默认收起。
3. **`知识库` 与 `知识探索` 未合并**（见 §4 的说明），两条路由并存。
4. **本机构建需要 `NODE_OPTIONS=""`**：宿主注入的 `node-language-shim.cjs` 会让 `next build` 的
   tracer 抛 `EPERM: open '.next/trace'`。这是**本机宿主环境问题，不是项目缺陷**；CI / Docker 构建不受影响。
5. **示例文案与任务书措辞不完全一致**：示例 Chip 与预填问题按本地知识库实际命中的问法选取，
   保证点了就有结果；语义与任务书一致。
6. **AI 调用有额度**：公开 Demo 的 AI 端点为 10 次/分钟/IP。本轮的引导设计刻意做到
   「填示例不自动提问 / 不自动生成 / 不自动运行」，避免访客的额度被引导动作消耗掉。
