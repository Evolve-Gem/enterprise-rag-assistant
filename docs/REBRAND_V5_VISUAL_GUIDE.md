# Enterprise RAG Copilot V5 — 全站视觉品牌重塑 · 视觉升级说明

**任务性质**：本地实现 + 本地验收（**未部署生产**）
**日期**：2026-10-09
**范围**：全站（框架层 + 10 个页面 + 全部核心组件）
**验收**：见 `docs/REBRAND_V5_QA_REPORT.md`；Before/After 对照见 `docs/images/rebrand-v5/`

## 0 ｜ 一句话

把产品从「一个做得比较整齐的企业知识库 Demo」升级为**「有品牌、有质感、有未来感、真正像作品的 AI 工作台」**——并且保证这件事**肉眼可感知**，而不是又一次"阴影更柔和一点"。

---

## 1 ｜ 本轮总目标

V4.2 已经把"每一层 surface 都是正确的"做到了：白卡墙被拆掉、对比度达标、深色是独立设计的。但 V4.2 的问题恰恰是**太安静**——它修正了错误，却没有建立身份。打开产品，你看到的是一个规整、克制、但并不记得住的界面。

本轮要解决的是**身份问题**，不是正确性问题：

1. 变化必须肉眼可感知（结构级，不是色值级）
2. 全站统一（首页与内页同级升级，禁止门面工程）
3. 高级感来自「克制 + 分层 + 氛围」，不是花哨
4. 每个关键页至少一个明确的视觉记忆点
5. 深色模式真实设计（不是翻色）
6. 可用性零牺牲（可读性、对比度、触控、焦点、reduced-motion 全部继续保持）

## 2 ｜ 视觉方向：为什么是 INK × AURORA（墨色框架 × 极光信号）

### 2.1 候选方向与取舍

| 方向 | 风格关键词 | 适用理由 | 风险 | 结论 |
|---|---|---|---|---|
| **A. INK × AURORA**（选定） | 墨色、极光、克制、未来感 | 用**一个恒定的深墨材质**同时承载「导航框架」与「旗舰瞬间」；浅色模式下产品第一次拥有强对比的品牌面；与"AI 工作台"的心智完全同构 | 浅色模式下深色框架是强主张，需要严格的对比度纪律 | **采用** |
| B. Paper & Graphite（纸与石墨） | 全浅色、编辑风、石墨灰 | 阅读体验舒适，最"安全" | AI 气质弱、浅深两态差异小、**变化可感知度不足**——正是 V4.2 的教训 | 否 |
| C. Terminal Archive（终端档案） | 等宽、网格、数据终端 | 工程可信度极强 | 偏极客、企业温度低，容易滑向"coder demo" | 否 |

### 2.2 选定方向的三个核心概念

**概念 1 — 墨色材质（INK）**：导航框架（侧边栏 / 顶栏 / 移动抽屉）在**两种主题下都是深墨**。这不是"暗色模式"，而是一种**恒定的材质**——像设备的边框。内容画布仍然随主题翻转。这一条是本轮**最可感知的变化**：浅色模式下第一次出现"深色驾驶舱 + 明亮工作区"的对比。

**概念 2 — 舞台材质（STAGE）**：同一块深墨材质，只用在 5 个旗舰瞬间：
- Home Hero（品牌宣言）
- Ask 空闲控制台 / 结果头带
- Agent 流程条
- Solution 流程条
- About 品牌 masthead

玻璃用满全站是模板，墨色用在五个确定的地方是**语言**。舞台上的文字使用**不随主题翻转**的浅色 token（舞台自己不翻转）。

**概念 3 — 极光信号（AURORA）**：紫→青的极光，alpha 恒定压在 ~35% 以下，只出现在墨面上：框架的 active 状态、舞台的氛围光、流水线连接线、每个结果头带底部的 1px 签名线。它是品牌唯一占有的信号色，因此**永远不碰浅色表面**。

### 2.3 为什么这个方向解决"AI 气质但不过度赛博"

极光只在**低透明度 + 大模糊**下出现（氛围，不是图案）；所有功能文案保持冷静的黑白灰；唯一的饱和度留给品牌信号与主 CTA。产品的情绪由**材质对比**（墨 vs 纸）产生，而不是由特效产生。

## 3 ｜ 与 V4.2 相比的关键变化（六个结构级动作）

> 判定标准：改的是**结构**，不是**色值**。以下每一条都能在 Before/After 对照里一眼看到。

### M1 墨色框架（Sidebar / Topbar / Mobile Drawer）
- 侧边栏、顶栏、移动抽屉从「白色 surface」变为**恒定深墨材质**，带品牌区氛围光（顶部极光晕染）
- 品牌区重做：极光渐变 monogram（紫→靛→青）+ 产品名 + 版本号 + tagline
- 导航 active 状态：**极光渐变竖条**（紫→青）+ 品牌色washed 背景 + 图标高亮——不再是浅色底上的浅色块
- 底部状态区改为**LED 仪表**：发光圆点 + 机关式排版
- 顶栏底部增加 **1px 极光签名线**（紫→青，两端淡出）

### M2 舞台材质（Stage）
- 新增 `.stage-panel` / `.aurora-field` 材质系统（墨色渐变 + 内嵌极光 + 顶部受光沿 + 颗粒 + 指针光晕）
- Home Hero 从「浅色玻璃」变为**深墨舞台**：浅色模式下首页第一屏 = 深色舞台 + 明亮工作区的强对比
- About 新增品牌 masthead 舞台
- `ResultSection` 头带全局变为**墨色舞台带**——所有结果（Agent / Solution / Gaps / Evaluation / Documents）开头都有一条深色带

### M3 排版放大与编辑节奏
- Hero 标题 26/32px → **27/36/40px**（响应式三档），字号第一次真正"顶"起来
- 全站页面标题 17px → **20px** + 新增 **kicker**（编号式小标签，如 `ASK` / `AGENT WORKSPACE`）
- 指标数字升级为 `.metric-value` 展示级数字（24/30px，tabular-nums）
- 新增 `Kicker` 原语：`index`（两位序号）+ `rule`（延伸细线）+ `tone`（light/stage）

### M4 首页重构（消灭"三张同款卡片"）
- 三个入口从「三张漂浮卡片」变为**一块连通的 Rail**：单一面板 + 内部细线分隔 + 头部 kicker 条（"从这里开始 · START HERE"）——**这是最直接的"去模板化"动作**
- "3 分钟体验"从第二组三卡片变为**编号示例列表**（单面板三行）——页面不再出现两组同构的三卡片
- "它是怎么工作的"从五个小盒子变为**编号节点流水线**（桌面节点圆 + 连接轨；手机紧凑编号列表）
- Demo 指标区从 12 个小盒子变为**仪表盘**（`gap-px` 细线网格 + 展示级数字），首次拥有"数据面"气质

### M5 阅读面与结果语言
- 每个结果以**墨色头带**开场（溯源徽章 + 延迟/模型/token + 1px 极光签名线），正文保持纸面浅色——墨是框，纸是活
- Ask 空闲态变为**墨色控制台**：示例提示词从"装饰 chips"变为**可点击的预填按钮**
- Agent / Solution 空闲态新增 **StageStrip 流程条**（描述目标 → … → 生成结果 + 引擎/输出说明），一条墨带同时承担"舞台瞬间"与"最短流程解释"

### M6 原语与状态体系
- `Button` 新增 `frame`（墨面幽灵按钮）与 `stage`（墨面玻璃按钮）两个变体——**为什么是变体而不是 className**：hover 色会与既有变体冲突，而 Tailwind 冲突工具的生效顺序由样式表顺序决定，不由类名顺序决定
- `Badge` 新增 4 个 ink 色阶（`ink / ink-accent / ink-success / ink-warning`）：语义色是为浅色面调校的，直接搬到墨面上会发浑
- 焦点环在墨面上自动切换为**提亮极光色**（WCAG 2.2 SC 1.4.11 的 3:1 约束）
- 侧边栏 LED 状态点、`FrameDot` 组件（发光圆点）

## 4 ｜ 逐页说明

| 页面 | 视觉记忆点 | 关键变化 |
|---|---|---|
| **Home** | 深墨舞台 Hero（极光 + 颗粒 + 指针光晕） | M1/M4 全部；首屏三入口保持（390 实测 719px < 844 视口） |
| **Ask** | 空闲：墨色控制台；结果：墨色结果头带 | 示例提示词可点击预填；回答正文保持纸面阅读宽度 |
| **Agent** | StageStrip 流程条（描述目标→…→生成结果） | 结果头带墨色化；Timeline/证据仍是原语言 |
| **Solution** | StageStrip 流程条（描述需求→…→导出交付） | 结果头带墨色化；8 章节阅读面不变 |
| **About** | 品牌 masthead 舞台（monogram + 定位语 + 技术栈 chips） | 版本历程时间线保留（V4.2 身份工作不推倒） |
| **知识中心**（Documents / Explorer / Gaps） | 继承新原语 | ResultSection 墨带、kicker、徽章/按钮新色阶 |
| **Evaluation / Activity / Settings** | 继承新原语 | 同上；不做结构重排（工具页保持密度） |

## 5 ｜ 设计系统 V3（tokens 摘要）

```
墨色框架（恒定，不随主题翻转）
  --color-frame / -deep / -line / -ink / -ink-soft / -ink-muted / -ink-faint
  --color-frame-hover / -active / -accent / -accent-soft

舞台（恒定）
  --color-stage / -deep / -line / -ink 系列 / -accent / -success / -warning / -danger
  --elevation-stage（黑色阴影 + 低透明紫光晕）

极光
  --aurora-violet / -indigo / -cyan / -wash

新原语
  .stage-panel / .aurora-field / .grain（复用）/ .kicker / .kicker-stage / .metric-value
  .ink-frame（框架材质基类）
```

所有既有 token（surface 六层 / elevation 四级 / 语义色 / 数据色）**保持不变**——本轮是**叠加身份层**，不是推倒 V4.2。

## 6 ｜ 本轮解决的核心问题

| 问题 | 解决方式 |
|---|---|
| 1. V4.2 变化不够显著 | 墨色框架 + 舞台材质 = 首屏强对比；四个结构级重构 |
| 2. 模板感仍在 | Rail（连通面板）替代卡片阵列；示例变列表；流水线变节点轨道；指标变仪表盘 |
| 3. 视觉重心不够强 | 每页恰好一个舞台瞬间（Hero / 控制台 / 流程条 / masthead / 结果头带） |
| 4. 品牌感不足 | 恒定的墨+极光材质、monogram、签名线、LED 仪表——不依赖任何一张配图 |
| 5. 全站一致性 | 所有页面共享同一组原语与 kicker 语言；框架层全局统一 |

## 7 ｜ 可用性底线（与 V4.2 同级保持）

- 移动端 44px 触控规则未动；Ask 首屏三入口完整（390 实测 719px）
- 对比度：舞台文字使用专用 token（近白 / 浅灰 / 中灰三档），焦点环在墨面自动提亮
- `prefers-reduced-motion`：极光漂移、浮动、呼吸全部归零（全局规则未动）
- 键盘：焦点陷阱 / 跳跃链接 / 真实 Tab 焦点环全部继承 V4.2 的修复
- 未引入任何运行期依赖；未改动任何交互逻辑、API 调用与文案语义
