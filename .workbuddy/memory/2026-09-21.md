## 方法沉淀：网申字数是硬约束，必须机器校验

「100/200/300/500 字」是投递平台的硬性输入限制，**凭感觉写必然超标**。
本次首稿实测 **166 / 373 / 704 / 868**，全部超标，最多超 74%。

迭代 6 轮才收敛到 **101 / 199 / 297 / 515**（±3%）。

**教训**：字数版本不要一次写完就算完，要**写→测→砍→再测**。
统计脚本已留存 `C:\agents\temp\resume_v41_count.py`（口径：去空白 + 去 Markdown 标记后的字符数）。

**砍字的有效手法**（按收益排序）：
1. 删掉「（文件名 + 章节 + 正文）」这类括号内举例 → 信息损失最小
2. 段落标记从「【一、业务场景与问题】」压成「【一、场景与问题】」
3. 合并同类项：「默认用 RRF 而非加权求和，因为两种分数不同量纲、加权需标定且参数会漂移」→「默认用 RRF，因两类分数不同量纲、加权需标定」
4. 去掉「通过」「进行」「相关」等虚词
5. **最后才砍事实**——数字和指标必须留住，它们是简历的价值所在
