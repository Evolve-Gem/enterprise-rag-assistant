## 踩坑（本轮最大的一条）

**`next build` 报 `EPERM: open '.next/trace'`，连试 4 次一模一样。**
先按习惯怀疑文件锁 → 手工 `fs.writeFileSync('.next/trace')` 与 `openSync(...,'a')` **都成功**，
`.next` 可写、磁盘 328G 可用、无僵尸 node 进程 → **不是锁**。
真因：宿主经 `NODE_OPTIONS=--require .../node-language-shim.cjs` 把 shim 注入**每一个** node 进程，
与 Next 构建 tracer 冲突。
**绕过（只给这一条命令）**：`NODE_OPTIONS="" node node_modules/next/dist/bin/next build`。
已同步到项目 MEMORY.md、用户级 MEMORY.md、以及 `windows-utf8-encoding-hardening` Skill。

**教训**：Node 工具在宿主里报奇怪 EPERM/EACCES 而手工 fs 正常时，**第一步就打印 `process.env.NODE_OPTIONS`**。
这和「先看 HTTP 状态码再怀疑业务」是同一类纪律 —— 先证伪自己的假设，再往下查。
