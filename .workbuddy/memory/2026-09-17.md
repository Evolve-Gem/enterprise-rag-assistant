**硬性规则（已写入 MEMORY.md）**：

## 追加：部署前同源构建修复 + v3.0.0 重新冻结与推送

### 用户抓到的真实缺陷（Critical）
`docker-compose.yml` 用 `${NEXT_PUBLIC_API_BASE_URL:-http://localhost:8000}` 传构建参数，
而 **POSIX 的 `:-` 在「值为空」时同样取默认值** —— 生产 `.env` 里 `NEXT_PUBLIC_API_BASE_URL=`（模板就是空）
会被静默改写成 `http://localhost:8000` 并烧进浏览器包，**直接废掉同源 `/api` 反代**。
`Dockerfile.web` 的 `ARG` 同样默认成该 URL，`.env.example` 也是（同一陷阱的第二处）。

修法：
- compose → `${NEXT_PUBLIC_API_BASE_URL-}`（**`-` 只在未设置时取默认**）
- `Dockerfile.web` → `ARG NEXT_PUBLIC_API_BASE_URL=`（空默认）
- `.env.example` → 默认空（同源），跨源写法降为注释

### 证据（含阳性对照，证明不是「改了就好了」）
- **阳性对照**：用 `http://localhost:8000` 构建 → **1 个 bundle 文件命中**（`.next/static/chunks/163-*.js`）
  ⇒ 证明扫描方法有效、旧默认值确实会泄漏
- 修复后：`NEXT_PUBLIC_API_BASE_URL=`（空）与未设置两条路径构建 → **均 0 命中**
- 产物内实际调用的是相对路径 `/api/rag/query`
- 同源回归：经前端端口 `/health` 200、`/api/settings` 200、`/api/knowledge/stats` 200 → **24 文档 / 283 chunks**
- 真实 Chromium：渲染真实数据、**0 console error、0 page exception、0 溢出**
- tsc 0 / ESLint 0-0 / build 14 路由 / **161 pytest** 全绿
