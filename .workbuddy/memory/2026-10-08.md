# 2026-10-08 · V4.2 Quality Recovery（进行中）

## 本轮最重要的发现：测得的数字可能全部无效，而它不会报错

V4.2 上一轮报出「919 处触控违规」，我据此写了 NOT READY。**那 919 是垃圾数据。**
根因链条：

1. 本机有 `http_proxy=http://127.0.0.1:35246`（WorkBuddy 沙箱代理）；
2. **Chromium 继承该变量，且不自动豁免回环地址** → 访问 `127.0.0.1:3001` 的请求有时被送进代理并失败；
3. 浏览器落到 Chrome 错误页，而**我的探针照样在上面量** —— 那 919 个「违规元素」的文本是
   **「检查代理服务器和防火墙」**，是 Chrome 错误页的链接。

**修法（三处缺一不可）**：
- Chromium 加 `--no-proxy-server` + `--proxy-bypass-list=<-loopback>`
- 启动环境清空 `http_proxy/https_proxy/HTTP_PROXY/HTTPS_PROXY/no_proxy`
- **服务启动 + 就绪验证 + 浏览器使用放在同一条命令内**（后台服务会随 shell 退出被回收）

**修复后有效结果**：7 视口 × 10 页面 = **70 组合，失败 0**；
错误页 0、横向溢出 0、console error 0、**触控违规 0**、38 条内部链接全 200。

## curl 在本机不能作为就绪判据

同一时刻 `curl 127.0.0.1:3001` 返回 `000`（--noproxy）或 `502`（走代理），而页面实际完全正常。
**就绪判定必须用 DOM**（`main` 存在 + 非错误页），而不是 HTTP 状态码。

2. **程序化 `.focus()` 不触发 `:focus-visible`** → 用它判断焦点环必然得出「没有描边」。
   改用**真实 Tab 键**后：`:focus-visible = true`、outline `2px solid rgb(79,70,229)`。
   **焦点相关验证必须走真实键盘路径**（与之前「测点击要用真实鼠标事件」同一类错误）。

另：把脚注写在 `{overview.data ? …}` 守卫**之外**会 tsc 报错（判别联合的收窄只在守卫内成立），
三元链的最后一个分支还只能接受**单个** JSX 表达式（需要 Fragment 包裹）。
